# Iteration Review Shape

在本仓库编写迭代复盘时，先完整阅读 `document/iteration-reviews/0000-Earth-clear统一输运迭代复盘.md`。把它作为清晰度、信息密度和详略分配的标尺，不复制具体内容、篇幅或格式。

## 章节职责

- `Scope`：提交范围、事实终点，以及后续真相由哪里维护。
- `Architecture`：范围终点的权威数据流、模块职责和关键边界；没有显著架构变化时不必展开。
- `Impact`：这批提交实际改变了什么、为何值得记录；业务含义和本轮特有的工程认识集中在这里。
- `Delivery`：原始要求达到什么程度，以及完成结论所带的限制。
- `Evidence`：实际存在的验证，以及它们能证明和不能证明的内容。
- `Next Steps`：影响总体判断的未完成项和后续不能破坏的边界；活跃任务仍进入控制平面。

这些章节只表示信息归属，不是填写模板。内容可按需省略或展开，内部可以使用自然段、标题、列表、表格、代码块或引用。

## 成文原则

- 开头先给阶段结论，让读者迅速获得总体把握。
- 普通事实简洁交代；重要部分展开到足以理解原因、选择和边界，讲清后停止。
- 形式服从信息关系，不为结构整齐平均分配篇幅，也不把文档写成 commit 或文件清单。
- 保持工程术语和证据资格准确；有依据的判断可以直接说，不能支持的结论明确收住。
