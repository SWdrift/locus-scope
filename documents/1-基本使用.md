# 基本使用

从创建 Scope 到组合 Package 完成一次基本使用流程。npm 或 pnpm 负责管理依赖，统一的 `locus-scope` 命令负责加载和操作 Workspace。

## 安装

准备使用 Package 声明的 Node.js LTS 版本，然后在项目中安装 TypeScript Locus package：

```text
pnpm add @sundw/locus-scope
```

## 创建第一个 Scope

创建 `app/locus.yaml`：

```yaml
id: app

exports:
  - backend
```

`locus.yaml` 定义一个 Scope。`id` 是它在内容中的名称；`exports` 列出允许其他 Scope 访问的 Entity。

在 `app/model/services.locus.yaml` 中定义 Entity 和 Relation：

```yaml
entities:
  - id: database
    type: postgres
    host: db.internal
    port: 5432

  - id: backend
    type: service

relations:
  - from: backend
    type: uses
    to: database
```

Entity 是包含必需标识字段 `id` 的开放对象。Relation 是包含 `from`、`type`、`to` 三个必需定位字段的开放对象。两者均可直接声明其他任意嵌套属性。

Definition document 使用 `.locus.yaml`、`.locus.yml` 或 `.locus.json` 后缀。Locus 会递归读取当前 Scope 下普通子目录中的这些文件。如果某个子目录有自己的 `locus.yaml`，它会被视为另一个独立 Scope，不会自动并入当前 Scope。

完成后的目录结构：

```text
app/
├── locus.yaml
└── model/
    └── services.locus.yaml
```

## 操作第一个 Scope

下面用一组最短操作完成 Workspace 验证、对象查询和关系图遍历。`file:///path/to/project/app` 表示 `app` 目录实际的绝对 file URI。

### 验证 Workspace

```shell
pnpm exec locus-scope --scope ./app validate
```

输出：

```json
{
  "valid": true,
  "root": "file:///path/to/project/app",
  "scopes": 1,
  "entities": 2,
  "relations": 1
}
```

`validate` 会加载并验证所有可达 Scope。

### 查询 Entity

先按引用读取 `database`：

```shell
pnpm exec locus-scope --scope ./app entity database
```

输出：

```json
{
  "key": {
    "scope": "file:///path/to/project/app",
    "id": "database"
  },
  "ref": "database",
  "object": {
    "host": "db.internal",
    "id": "database",
    "port": 5432,
    "type": "postgres"
  }
}
```

也可以按开放属性筛选：

```shell
pnpm exec locus-scope --scope ./app entity type=postgres
```

输出：

```json
[
  {
    "key": {
      "scope": "file:///path/to/project/app",
      "id": "database"
    },
    "ref": "database",
    "object": {
      "host": "db.internal",
      "id": "database",
      "port": 5432,
      "type": "postgres"
    }
  }
]
```

多个 filter 使用 AND；例如 `entity type=postgres port=5432`。

### 查询 Relation

```shell
pnpm exec locus-scope --scope ./app relation type=uses
```

输出：

```json
[
  {
    "fromKey": {
      "scope": "file:///path/to/project/app",
      "id": "backend"
    },
    "toKey": {
      "scope": "file:///path/to/project/app",
      "id": "database"
    },
    "object": {
      "from": "backend",
      "to": "database",
      "type": "uses"
    }
  }
]
```

`fromKey` 和 `toKey` 是解析后的稳定 owner key；`object` 保留声明中的引用和其他开放属性。

### 遍历关系图

从 `backend` 沿出边查询一层：

```shell
pnpm exec locus-scope --scope ./app graph backend --depth 1
```

输出包含 seed、两端 Entity 和 `backend → database` Relation：

```json
{
  "seeds": [
    {
      "key": {
        "scope": "file:///path/to/project/app",
        "id": "backend"
      },
      "ref": "backend",
      "object": {
        "id": "backend",
        "type": "service"
      }
    }
  ],
  "depth": 1,
  "nodes": [
    {
      "key": {
        "scope": "file:///path/to/project/app",
        "id": "backend"
      },
      "ref": "backend",
      "object": {
        "id": "backend",
        "type": "service"
      }
    },
    {
      "key": {
        "scope": "file:///path/to/project/app",
        "id": "database"
      },
      "ref": "database",
      "object": {
        "host": "db.internal",
        "id": "database",
        "port": 5432,
        "type": "postgres"
      }
    }
  ],
  "relations": [
    {
      "fromKey": {
        "scope": "file:///path/to/project/app",
        "id": "backend"
      },
      "toKey": {
        "scope": "file:///path/to/project/app",
        "id": "database"
      },
      "object": {
        "from": "backend",
        "to": "database",
```

同一组数据还可以回答另外两类图问题：

- `path backend database` 返回从 `backend` 到 `database` 的最短有向路径。
- `impact database` 沿入边反向查询，返回受 `database` 影响的 `backend`。

### 其他关键操作

| 目的                      | 命令                               |
| ------------------------- | ---------------------------------- |
| 查看 root Scope           | `scope .`                          |
| 列出或筛选 Group          | `group [<group-ref>\|<filter>...]` |
| 列出全部 Entity           | `entity`                           |
| 列出全部 Relation         | `relation`                         |
| 新增、修改或删除 Entity   | `entity add\|set\|unset\|remove`   |
| 新增、修改或删除 Relation | `relation add\|set\|unset\|remove` |
| 比较两个语义子图          | `diff <selector-a> <selector-b>`   |
| 显示声明来源              | 在查询命令后追加 `--source`        |

进入 `app` 或其子目录后可以省略 `--scope ./app`。默认的格式化 JSON 适合交互阅读；Agent、脚本或 CI 可以追加 `--json` 获得稳定的单行 JSON。所有命令、参数、筛选、写入和退出状态见 [CLI 参考](3-CLI参考.md)。

## 组合本地 Scope

假设同级目录 `infra/` 也是一个 Scope，并且导出了 `database`。在 `app/locus.yaml` 中添加相对 Import：

```yaml
id: app

imports:
  infra: ../infra

exports:
  - backend
```

`infra` 是当前 Scope 为这次 Import 指定的别名。通过该别名检查被导出的 Entity：

```text
pnpm exec locus-scope --scope ./app entity infra:database
```

## 组合 Package

安装一个已发布的 Locus Package：

```text
pnpm add @example/infra
```

然后把 `app/locus.yaml` 的 Import 改为 Package 名：

```yaml
id: app

imports:
  infra: "@example/infra"

exports:
  - backend
```

再次验证并检查：

```text
pnpm exec locus-scope --scope ./app validate
pnpm exec locus-scope --scope ./app entity infra:database
```

`locus.yaml` 只写 Package 名，不写版本和子路径。版本范围保存在 `package.json.dependencies`，确定版本由 `pnpm-lock.yaml` 固定。

## npm 与 pnpm

npm 使用相同的文件和语义。把安装命令及执行前缀替换为：

```text
npm install @sundw/locus-scope @example/infra
npx locus-scope --scope ./app validate
```

更多依赖管理边界见 [npm 模式](2-使用npm.md)。
