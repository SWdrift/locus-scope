# 测试设计

## 简述

测试证明 Core semantics、稳定 application API、resolved Package environment、npm Package 生命周期和消费层可观察协议。选择能完整观察契约的最低层级，不按源码函数逐一覆盖。

## 分层

- **Domain**（`test/unit/domain.test.ts`）：协议、Workspace、Source ownership 和诊断；package manager 类型不得进入该层。
- **Application API**（`test/unit/application.test.ts`）：稳定 DTO、排序、ownership、reference resolution、graph、diff 和 mutation；不重复测试无分支构造、转换与转发。
- **Package environment**（`test/unit/package-environment.test.ts`）：identity、resolved edges、entry 边界与 Scope Resolver。
- **CLI / Node API**（`test/unit/application.test.ts`、`src/cli`）：只覆盖参数、transport、Environment、输出与退出状态，不重复 application 或 domain semantics。

测试工作区、fixture、Registry 配置、凭据和观测状态必须位于仓库内。Node package-manager 的 store/cache 使用机器级配置，不得重定向到仓库。

## 注册测试边界

### Core

保留既有 composition、discovery、Group、re-export、cycle、相同 manifest ID 不同 Source、Resolver identity、诊断和 root discovery 用例，并增加开放 Relation、三元组语义唯一、完整 provenance、Filter/Selector、multigraph traversal、single-file synthetic Scope、mutation atomicity 与 dependency read-only。每项测试直接观察领域边界，不测试第三方库本身。

### Package environment

- identity、root dependencies 与 importer-relative edges。
- root local Source 与 npm Package Source 的不同路径规则。
- dependency target 缺失、entry escape、非 Scope manifest 和冲突 identity。
- 多版本同名 dependency 按 importer edge 解析并保持原始 ownership。


### Application API 与消费层

- Application API 覆盖统一 query envelope、稳定排序、root ref 可选性、provenance、graph depth/via、确定最短 path、reverse impact、semantic diff 和 mutation result。
- application error 测试覆盖高价值 Code/Reason/Details、cause 保留和未分类错误转换；CLI 集中验证一次 exit code 映射，不逐 reason 重复。
- CLI 只覆盖 command grammar、stdin、usage、exit 2/1、stdout/stderr 与稳定 JSON；不重复 application semantics。
- library API 和 CLI 验证同一 domain/application 实现；不存在单独 host protocol。
- synthetic hoisted 与 pnpm symlink layouts 生成相同 Environment；blocked exports、missing dependency、entry escape 和冲突 identity diagnostics 保持覆盖。

## npm Lifecycle E2E

唯一主闭包为 `TestNPMPackageLifecycle`。E2E 自行启动 Verdaccio 6.10.2 child，使用动态 loopback port；config、storage、auth、log、fixtures 和 result 全部位于 `temp/e2e-run/npm/`。测试只停止自己验证过的 child，并保留完整现场。

Fixtures 位于 `test/e2e/case/npm/`。场景必须观察：

1. 通过标准 npm Registry 流程发布 base、helper 与 app fixtures。
2. 发布 `@sundw/locus-scope` package。
3. 在隔离 consumer 中使用 pnpm 安装最终 Package。
4. 运行真实 `locus-scope`，验证 transitive Package Scope、exact identity、Entity 与 path 查询。
5. Package manager store/cache 保持机器级配置；测试 userconfig、HOME、Registry 和运行状态全部位于仓库内。

## npm 发布验收

`pnpm run release:npm` 必须生成主 Package tarball。`pnpm run verify:npm-release` 从最终 tarball 安装隔离 consumer，运行真实 `locus-scope validate --json`，并通过公开 library API 得到 `valid: true`。

## 隔离与现场

- 可复用声明和模拟状态只放在 `test/e2e/case/`。
- 运行时具现化到 `temp/e2e-run/`；新运行确定性替换对应目录。
- 不读取或修改 workspace 外用户配置、凭据、服务、网络或文件。
- npm/pnpm 使用测试专用 userconfig/HOME 环境变量；Registry 仅使用 loopback。
- 测试结束保留 fixtures、Registry 状态和解析结果，便于手动复现。

## 完成标准

```text
pnpm run check
pnpm run typecheck
pnpm test
pnpm run test:e2e
pnpm run release:npm
pnpm run verify:npm-release
```

开发 Registry 另行 smoke：依次执行 `pnpm run registry:start`、`pnpm run registry:status`、`pnpm run registry:stop`、`pnpm run registry:reset`。测试入口不得启动或读取开发 Registry；E2E 必须拥有隔离 Registry child。
