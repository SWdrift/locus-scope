# 测试设计

## 简述

测试证明 Core semantics、npm Package 生命周期、两个 package environment 和 CLI 可观察行为。选择能完整观察契约的最低层级，不按源码函数逐一覆盖。

## 分层

- **Core**（`internal/scope/*_test.go`）：协议、Workspace、Source ownership 和诊断；package manager 类型不得进入该层。
- **Package environment**（`internal/packageenv/*_test.go`）：identity、Import 分类、importer-relative edges 与 npm package Scope 边界。
- **npm protocol**（`internal/npm/*_test.go`）：name/spec/SemVer、Registry/auth、SRI、archive safety、packlist 与 publish body。
- **Pure package manager**（`internal/purepkg/*_test.go`）：strict lock、resolver graph、store、事务、offline/frozen 与 package.json mutation。
- **CLI / Node**（`cmd/*_test.go`、`packaging/npm/locus-scope/test/*.test.mjs`）：命令、JSON 协议、descriptor、platform host 与输出转发。
- **E2E**（`test/e2e/*_test.go`）：真实 Verdaccio、标准 npm/pnpm、standalone binary 和 Node package 的完整 lifecycle。

测试工作区、fixture、Registry 配置、凭据和观测状态必须位于仓库内。Node package-manager 的 store/cache 使用机器级配置，不得重定向到仓库。

## 注册测试边界

### Core

保留既有 composition、discovery、Group、re-export、cycle、相同 manifest ID 不同 Source、Resolver identity、诊断和 root discovery 用例。只把旧 package identity 预期调整为 `npm:<name>@<version>`；不改变 Scope/Graph 语义。

### Package environment

- Identity 和 bare/local/absolute Import 分类。
- root local Source 与 npm package Source 的不同路径规则。
- importer dependency map 缺失 edge、target 缺失和 graph identity 冲突。
- 多版本同名 dependency 按 importer edge 解析并保持原始 ownership。
- package.json strict validation、唯一 Scope manifest、entry escape、undeclared Scope Import 和 blocked package.json export。

### npm protocol

- scoped/unscoped name 与 package spec；exact/range npm SemVer。
- Registry precedence、scoped override、`.npmrc` interpolation、longest-prefix Bearer token 和 unsupported credential rejection。
- packument/version/download/publish URL、size limit、timeout、redirect origin 和 immutable 409。
- SHA-512/SHA-256 SRI、corrupt bytes、unsafe/duplicate/link/device/FIFO/sparse tar entries 和 extraction limits。
- reduced packlist 的 files literal、always-included/excluded files、symlink/lifecycle/.npmignore rejection 和 deterministic tgz。
- publish body 的 dist-tag、shasum、integrity 和 attachment。

### Pure package manager

- strict/canonical lock：unknown/duplicate fields、排序、root mirror、edge target、unreachable node、identity/source/content conflict。
- cache/store integrity 与 metadata revalidation；普通 npm package 锁定但不进入 Scope environment。
- changed-root closure resolution、unchanged subgraph reuse、named/all update、uninstall prune 和 conflicting environment。
- explicit install package.json mutation、frozen mismatch、offline completeness、atomic commit/rollback 和 newly published store cleanup。
- install/uninstall/update/list/pack/publish result contracts。

### CLI 与 Node

- options 位于命令前后、usage exit 2、operational exit 1 和稳定 JSON failure。
- root discovery、version 无 Scope、list tree 与 text/JSON stable fields。
- Node request strict decode、trailing JSON、path/entry escape、identity conflict 和 response/exit forwarding。
- synthetic hoisted 与 pnpm symlink layouts 生成相同 descriptor。
- blocked exports、platform mismatch、missing host 和 unsupported platform diagnostics。

## npm Lifecycle E2E

唯一主闭包为 `TestNPMPackageLifecycle`。E2E 自行启动 Verdaccio 6.10.2 child，使用动态 loopback port；config、storage、auth、log、fixtures、binary 和 result 全部位于 `temp/e2e-run/npm/`。测试只停止自己验证过的 child，并保留完整现场。

Fixtures 位于 `test/e2e/case/npm/packages/{base,app,modern,helper,private}` 及 consumers：

- 发布 `@example/base` 1.0.0、1.1.0、2.0.0。
- `@example/app@1.0.0` 依赖 base `^1` 与没有 `locus` 的 helper。
- `@example/modern@1.0.0` 依赖 base `^2`。
- consumer 同时 Import app 和 modern，证明 base v1/v2 coexist、importer-relative edge 和 `npm:` ownership；helper 安装但不进入 Scope graph。

场景必须观察：

1. 标准 npm 发布 fixture，并检查 packument、dependency metadata、tgz download 和 integrity。
2. Pure `locus-pkg install @example/app@^1 @example/modern@^1`，检查 lock/store 和 standalone queries。
3. 停止 Registry 后检查 offline 输出；Pure subprocess 的 PATH 移除 Node/npm/pnpm locations，但保留必需 OS 目录。
4. 后发布 base 1.1.0：新项目选择 1.1.0，旧 lock 保持 1.0.0，named update 仅推进 app closure，frozen mismatch 不改变 bytes。
5. `locus-pkg pack` 与 `publish` 新 fixture，下载回验，并分别由 npm 与 pnpm 安装。
6. 发布 `@locus/scope` 与当前平台 package，在独立 npm/pnpm consumer 中运行 `locus-scope-node`；规范化 Scope/Entity/Relation JSON 与 Pure 结果一致。
7. 创建确定性 Verdaccio 用户，token 只写入 isolated temp userconfig；覆盖 authenticated private publish/install、missing/wrong token，并扫描 package.json/lock/.locus/results 确认无 token。
8. 拒绝 integrity mismatch、unsafe tar、unsupported spec、duplicate Scope manifest、blocked package.json export、immutable version conflict，并证明 failed install rollback。

## 隔离与现场

- 可复用声明和模拟状态只放在 `test/e2e/case/`。
- 运行时具现化到 `temp/e2e-run/`；新运行确定性替换对应目录。
- 不读取或修改 workspace 外用户配置、凭据、服务、网络或文件。
- npm/pnpm 使用测试专用 userconfig/HOME 环境变量；Registry 仅使用 loopback。
- 测试结束保留 fixtures、binary、SQLite/Registry 状态和解析结果，便于手动复现。

## 完成标准

```text
pnpm run check:links
go test ./internal/scope ./internal/packageenv ./internal/npm ./internal/purepkg ./internal/scopecli ./cmd/locus-scope ./cmd/locus-pkg ./cmd/locus-scope-node-host -count=1
pnpm run test:node
pwsh -File scripts/test-run.ps1 e2e
pwsh -File scripts/test-run.ps1 all
pwsh -File scripts/inno-setup.ps1 install
pwsh -File scripts/release-package.ps1
```

开发 Registry 另行 smoke：`scripts/npm-registry.ps1 start`、`status`、`stop`、`reset -Force`。测试入口不得启动或读取开发 Registry；E2E 必须拥有独立 Registry child。
