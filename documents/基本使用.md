# 基本使用

本文从创建 Scope 到组合 Package 完成一次基本使用流程。示例以 pnpm 管理依赖的 npm 模式为主；独立 CLI 模式只在最后列出差异。

## 安装

准备 Node.js 20.6 或更新版本，并在项目中安装 Node adapter：

```text
pnpm add @sundw/locus-scope
```

## 创建第一个 Scope

创建 `app/locus.yaml`：

```yaml
id: app

exports:
    - backend
```

`locus.yaml` 定义一个 Scope。`id` 是它在内容中的名称；`exports` 列出允许其他 Scope 访问的 Entity。

在 `app/model/services.locus.yaml` 中定义 Entity 和 Relation：

```yaml
entities:
    - id: database
      type: postgres
      host: db.internal
      port: 5432

    - id: backend
      type: service

relations:
    - [backend, uses, database]
```

Entity 是有身份和属性的对象。Relation 使用 `[起点, 关系, 终点]` 三元组描述 Entity 之间的有向关系。

Definition document 使用 `.locus.yaml`、`.locus.yml` 或 `.locus.json` 后缀。Locus 会递归读取当前 Scope 下普通子目录中的这些文件。如果某个子目录有自己的 `locus.yaml`，它会被视为另一个独立 Scope，不会自动并入当前 Scope。

## 验证和检查

从项目根目录执行：

```text
pnpm exec locus-scope-node --scope ./app validate
pnpm exec locus-scope-node --scope ./app entity list
pnpm exec locus-scope-node --scope ./app entity show database
pnpm exec locus-scope-node --scope ./app relation list
pnpm exec locus-scope-node --scope ./app resolve database
```

各命令的用途：

| 命令 | 结果 |
| --- | --- |
| `validate` | 验证完整 Workspace，并统计 Scope、Entity 和 Relation。 |
| `entity list` | 列出所有可达 Entity 及其 owner。 |
| `entity show <ref>` | 显示指定 Entity 的 owner、ID 和属性。 |
| `relation list` | 列出验证后的 Relation。 |
| `resolve <ref>` | 把引用解析为最终 owner 和 Entity ID。 |

进入 `app` 或其子目录后可以省略 `--scope ./app`。追加 `--json` 可以获得适合 Agent、脚本和 CI 的稳定 JSON 输出。

## 组合本地 Scope

假设同级目录 `infra/` 也是一个 Scope，并且导出了 `database`。在 `app/locus.yaml` 中添加相对 Import：

```yaml
id: app

imports:
    infra: ../infra

exports:
    - backend
```

`infra` 是当前 Scope 为这次 Import 指定的别名。通过该别名检查被导出的 Entity：

```text
pnpm exec locus-scope-node --scope ./app resolve infra:database
```

Import 不会复制 Entity，也不会改变原始 ownership。未在目标 Scope 的 `exports` 中公开的 Entity 不能通过 Import 访问。

## 组合 Package

安装一个已发布的 Locus Package：

```text
pnpm add @example/infra
```

然后把 `app/locus.yaml` 的 Import 改为 Package 名：

```yaml
id: app

imports:
    infra: "@example/infra"

exports:
    - backend
```

再次验证并检查：

```text
pnpm exec locus-scope-node --scope ./app validate
pnpm exec locus-scope-node --scope ./app resolve infra:database
```

`locus.yaml` 只写 Package 名，不写版本和子路径。版本范围保存在 `package.json.dependencies`，确定版本由 `pnpm-lock.yaml` 固定。

## npm 与 pnpm

npm 使用相同的文件和语义。把安装命令及执行前缀替换为：

```text
npm install @sundw/locus-scope @example/infra
npx locus-scope-node --scope ./app validate
```

更多依赖管理边界见 [npm 模式](使用npm.md)。

## 独立 CLI 模式的差异

独立 CLI 模式不改变 Scope、Entity、Relation、Import 或 Export 的写法，只替换命令入口和 Package 管理方式：

| npm 模式 | 独立 CLI 模式 |
| --- | --- |
| `pnpm exec locus-scope-node ...` | `locus-scope ...` |
| `pnpm add @example/infra` | `locus-pkg install @example/infra@^1.0.0` |
| `pnpm-lock.yaml` 与 `node_modules` | `locus.lock` 与 `.locus/` |
| 需要 Node.js 和 npm/pnpm | 不需要 Node.js、npm 或 pnpm |

例如，独立 CLI 完成同一检查：

```text
locus-pkg install @example/infra@^1.0.0
locus-scope --scope ./app validate
locus-scope --scope ./app resolve infra:database
```

独立 CLI 的安装、离线运行和发布方式见[独立 CLI 模式](使用独立CLI.md)。
